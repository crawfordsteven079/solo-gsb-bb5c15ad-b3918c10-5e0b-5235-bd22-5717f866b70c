# 纸质展品光照额度管理系统

面向纸质展品（书画、手稿、文献等）的**年度照度时数（lux·h）额度**管理 Web 应用。
由本地账号区分两类角色：

- **保管员（conservator）**：登记展品与每个自然年的照度时数上限；审批展出计划；展后录入并确认实测；处理待复核计划。
- **布展员（installer）**：提交展出计划（展期、每日开灯时段、预计照度），查看审批结果，撤销待审批计划。

## 功能与业务规则

- **按自然年拆分预计剂量**：计划给出展期 `[开始日, 结束日]`、每日开灯时段（不跨夜）、预计照度（lux）。
  系统把 `照度 × 每日开灯小时 × 当年天数` 按自然年拆分得到各年度预计剂量（单位 lux·h）。
- **计划时间重叠校验**：同一展品“展期 × 每日开灯时段”发生正向重叠的计划不得批准（仅端点接触允许：如一个 09:00–12:00、另一个 12:00–15:00 可同时存在）。
- **批准时额度合计**：批准时合计
  ① 该展品所有**已确认实测剂量**，② 其他已批准/待复核计划**尚未被实测替代的估算剂量**，③ 本计划新增剂量。
  任一自然年超过该年上限即拒绝，并明确指出**年份与超额量（lux·h）**；未登记上限的年度同样无法批准。
- **并发不超配**：批准在单个数据库事务中对“展品审批锁”加 `FOR UPDATE` 行锁，
  同一展品上的并发审批/实测确认被数据库串行化，杜绝并发批准导致的额度超配。
- **实测替代估算**：展后保管员录入“已批准/待复核”计划开灯时段内的实测（日期、时段、实测照度），先为“待确认”；
  确认后该时段以实测剂量计入，并按被覆盖时段的原估算剂量从该计划估算中扣除（而不是重复累加）。
- **重叠实测拒绝**：确认时若与同展品其他已确认实测在时间上正向重叠，整笔确认被拒绝。
- **迟到实测与待复核级联**：若某条迟到实测确认后造成某自然年超限，该展品在**相应年度内尚未开始的已批准计划**自动转为“待复核”，
  原审批记录（审批人/时间）与全部测量记录均保留；保管员复核后可再次批准或拒绝。
- **额度看板**：展品详情页按年展示年度上限、已占用（实测 + 估算剩余）、剩余额度，并列出每一项占用来源（哪条计划/哪次实测、各多少 lux·h）。
- **输入校验**：无效日期、结束早于开始、跨夜/零长度时段、非正（≤0）照度等都会返回明确错误。

剂量口径：`剂量(lux·h) = 照度(lux) × 时长(h)`。

## 技术栈

- Node.js 20 + Express 4（EJS 服务端页面）
- PostgreSQL 16（事务、行级锁）
- `pg` 数据库驱动、`express-session` + `connect-pg-simple` 会话、`bcryptjs` 密码哈希

## 一键启动（Docker Compose）

前置：已安装 Docker 与 Docker Compose 插件。

```bash
docker compose up --build
```

首次启动会自动：等待数据库就绪 → 执行幂等建表（`src/db/schema.sql`）→ 初始化两个本地账号 → 启动 Web。

访问地址与端口：

- Web 应用： **http://localhost:3000**
- PostgreSQL（可选，本机调试用）：`localhost:5432`

停止：`Ctrl+C`，或在另一终端执行 `docker compose down`（数据保留在命名卷 `pgdata` 中）。
清空数据重新初始化：`docker compose down -v`。

### 默认本地账号

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 保管员 | `conservator` | `conservator123` |
| 布展员 | `installer` | `installer123` |

## 配置

所有配置通过环境变量注入；`docker compose` 已内置默认值，开箱即用。
如需修改，复制模板并编辑：

```bash
cp .env.example .env
```

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `3000` | Web 应用在宿主机的映射端口（容器内固定 3000） |
| `PG_PORT_HOST` | `5432` | PostgreSQL 在宿主机的映射端口 |
| `PGUSER` | `lightuser` | 数据库用户 |
| `PGPASSWORD` | `lightpass` | 数据库密码 |
| `PGDATABASE` | `lightquota` | 数据库名 |
| `SESSION_SECRET` | `please-change-this-secret` | 会话签名密钥，**生产环境务必修改** |
| `CONSERVATOR_USER` / `CONSERVATOR_PASSWORD` | `conservator` / `conservator123` | 保管员账号（启动时幂等同步） |
| `INSTALLER_USER` / `INSTALLER_PASSWORD` | `installer` / `installer123` | 布展员账号（启动时幂等同步） |
| `TZ` | `Asia/Shanghai` | 时区；每日开灯时段按此时区的本地挂钟时间解释 |

> 容器之间通过内网服务名 `db:5432` 互连，无需对外暴露数据库即可使用。

## 使用流程

1. 以**保管员**登录 → “登记新展品” → 在展品详情页为相关自然年登记“年度照度时数上限”。
2. 退出，以**布展员**登录 → “提交新计划”：选择展品、填写展期、每日开灯/关灯时间、预计照度 → 提交。
3. 以**保管员**在“展出计划审批”中打开计划：页面给出批准前各年度试算（上限/已占用/新增/合计/超额）。
   - 有时间重叠或任一年超限：只能拒绝（页面会列出年份与超额量）。
   - 试算通过：点击“批准”。
4. 展后，**保管员**在计划详情页“录入该计划实测”，保存后为“待确认”；核对无误点“确认”。
   - 与既有已确认实测重叠会被拒绝；
   - 确认后该时段按实测计入、估算相应扣减；
   - 若因此超限，相应年度尚未开始的已批准计划自动转“待复核”，可在计划页再次批准/拒绝。
5. 展品详情页随时查看各年度剩余额度及每条占用来源。

## 本地开发（不使用 Docker）

需自行准备一个可连接的 PostgreSQL 14+，并设置连接环境变量：

```bash
npm install
export PGHOST=127.0.0.1 PGPORT=5432 PGUSER=lightuser PGPASSWORD=lightpass PGDATABASE=lightquota
npm start          # 自动建表 + 初始化账号 + 启动，默认 http://localhost:3000
```

运行核心规则测试（无需数据库）：

```bash
npm test
```

## 目录结构

```
src/
  server.js            启动入口：等待 DB → 建表 → 初始化账号 → 监听
  app.js               Express 装配（会话、权限、视图、路由）
  db.js                连接池、事务封装 withTransaction、建表

  db/schema.sql        表结构（幂等可重复执行）
  lib/dose.js          剂量按自然年拆分、重叠判定、额度汇总等纯函数
  lib/validation.js    表单输入校验
  middleware/auth.js   登录与角色中间件
  routes/              auth / exhibits / plans / measurements
  views/               EJS 页面
  public/styles.css    样式
test/dose.test.js      核心业务规则测试
Dockerfile             应用镜像（含依赖与初始化）
docker-compose.yml     db + app 一键编排
.env.example          配置模板
```
